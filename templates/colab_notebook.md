# Colab 筆記本排版規範

> 寫給 AI 看：專案要用 Google Colab 雲端算力（GPU）時，筆記本照這份規範寫。
> 起點：複製同資料夾的 `colab_notebook.ipynb` 骨架到專案的 `colab/`，再依專案填寫；不要從空白筆記本開始。
> 依據：Google 官方表單範例 `colab.research.google.com/notebooks/forms.ipynb`；pdf2epub 版面模型試跑筆記本試作，使用者確認風格（2026-10-20）。

## 1. 格子順序（固定）

| 順序 | 格子 | 內容 |
|---|---|---|
| 0 | 說明（Markdown） | 標題（一個 emoji ＋ 專案名稱：用途）、一句話說明、資訊表（執行階段：L4／A100／G4 GPU 建議、預估時間、要準備、會得到）、「🚀 使用方式」編號步驟、⚠️ 注意事項 |
| — | `## ⚙️ 設定` | 小標題（給左側目錄用） |
| 1 | ⚙️ 設定 | 所有可調整的參數，只放 `# @param` |
| — | `## ▶️ 執行` | 小標題 |
| 2 | 🧰 準備：載入顯示工具 | 骨架內建，原樣保留 |
| 3 | 1️⃣ 確認有分到 GPU | 沒分到就顯示 ❌ 與操作步驟並停止 |
| 4 | 2️⃣ 建立環境並安裝套件 | 已安裝就略過；最後顯示套件版本表 |
| 5 | 3️⃣ 準備輸入 | 上傳檔案或掛載雲端硬碟 |
| 6+ | 4️⃣… 執行 | 一格一件事 |
| — | `## 📦 結果` | 小標題 |
| 最後 | N️⃣ 打包並下載結果 | 打包 zip、顯示大小、說明要放回本機哪個資料夾、下載 |

## 2. 每一格的寫法

- 程式格第一行：`# @title N️⃣ 動詞開頭的步驟名稱 { display-mode: "form" }`，讓 Colab 只顯示標題、把程式碼摺起來。
- 第二行用 `# @markdown` 寫一句這格在做什麼、使用者要做什麼（例如「按下方選擇檔案」）。
- 一格只做一件事；使用者要操作的步驟（上傳、授權）獨立成一格。
- 說明格與 `@title`、`@markdown` 用繁體中文；Markdown 說明格只放一層 `#` 大標題，其他用 `##`、`###`（`metadata.colab.toc_visible` 設為 `true`，左側目錄才會展開）。
- 每格都要能重跑：已完成的步驟（例如已安裝）偵測後顯示 ℹ️ 並略過，不要重做或報錯。

## 3. 參數

- 可調整的值全部集中在「⚙️ 設定」格，用 `# @param`（勾選框 `{type:"boolean"}`、下拉選單 `["a", "b"]`、數字 `{type:"integer"}`）；後面的格子只讀變數，不再出現寫死的設定值。
- 參數旁用 `# @markdown` 說明影響（例如「越高越清楚、越慢」）。

## 4. 輸出

- 只用骨架「🧰 準備」格提供的函式：`ok()`、`warn()`、`fail()`、`info()` 卡片，`table_html()` 表格，`logbox()` 可展開的長訊息。不要用 `print` 輸出大段文字。
- 指令一律用 `sh(指令, "中文標題")` 執行，不用 `!指令`：成功只顯示 ✅＋秒數，失敗顯示 ❌＋最後 40 行訊息並停止「全部執行」。
- 要停止時 `raise StopRun(...)`，不要讓 Python 錯誤追蹤整片顯示。
- 長時間的程式用 `subprocess.Popen` 逐行讀輸出：子程式印 `@@` 開頭的進度標記（例如 `@@PAGE 名稱 3`），主格解析後用 `display(..., display_id=True)` ＋ `.update()` 更新進度表；其他雜訊不顯示，完整輸出寫進 `result/_run_log.txt`，跟結果一起打包。
- 跑完顯示彙總表（每項的耗時、資源用量、✅／❌）；失敗的項目另外用 `fail()` ＋ `logbox()` 顯示錯誤最後 15 行。
- 顏色只用卡片內建的四種；表格線用半透明灰（`#8884`），深色、淺色主題都看得清楚。

## 5. 硬體加速器（GPU）選擇指引

專案使用 GPU 雲端算力（如影像生成、影片生成、大語言模型推論、版面分析）時，說明格與第 1 格應註明建議的 GPU。

> **核心原則**：各 GPU 型號影響的是**推論速度（耗時）**與**顯示記憶體上限（VRAM，能載入的模型大小）**；相同模型權重與參數下，**產出的畫面品質與物理效果完全相同**。

| 硬體選項 | 架構與顯存 (VRAM) | 特性與生成耗時 | 適用情境與建議 |
|---|---|---|---|
| **L4 GPU** | NVIDIA Ada Lovelace<br>**24GB VRAM** | **標準速度**<br>支援 BF16/FP8，顯存充裕，生成時間適中（推測，未實測） | **預設首選（CP 值最高、最省點數）**。<br>Colab Pro 標配；畫面品質同旗艦卡，適合日常算力與完整流程驗證。 |
| **A100 GPU** | NVIDIA Ampere<br>**40GB / 80GB VRAM** | **極速**<br>大顯存與超高頻寬，耗時約為 L4 的 1/2 ~ 1/3（推測，未實測） | **長篇大量運算首選**。<br>適合不想久候、處理超長視訊或多個大型模型同時載入時使用。 |
| **G4 GPU** | NVIDIA Blackwell<br>(RTX PRO 6000 Server 等級，**96GB GDDR7** / 96GB VRAM) | **最快旗艦**<br>最新架構，極致推論效能，耗時最短（推測，未實測） | **旗艦極速配置**（見於 Colab Pro+ 或特定選單）。<br>耗點較多，適合追求極限速度出片或最新架構專案。 |
| **T4 GPU** | NVIDIA Turing<br>**16GB VRAM** | 較慢，不支援 BF16，大模型容易記憶體不足 (OOM) | 僅適合輕量影像處理、文字分類或教學測試；**現代 DiT 影音生成不建議使用**。 |

- **提示使用者**：在筆記本開頭資訊表註明「追求省點數選 L4，追求速度選 A100 或 G4；成片畫質皆相同」。
- **檢查格**：筆記本「1️⃣ 確認有分到 GPU」格，應相容 L4、A100、G4、T4 等不同卡別，在卡片上顯示目前分到的卡名、顯存大小與友善提示。

## 6. 環境

- Colab 內建套件與專案需要的版本衝突時，用 `uv` 建立獨立環境 `/content/venv`（Python 版本與本機 `.venv` 相同），套件版本與本機 `requirements.txt` 一致並鎖定。
  - 已知衝突（2026-10-20）：Colab 內建 PyTorch 與 Paddle 的 NCCL 衝突（`undefined symbol: ncclCommWindowDeregister`）；移除內建 PyTorch 會留下殘缺檔案（`No module named 'torch.multiprocessing'`）。用獨立環境後正常。
- 安裝完執行一次檢查（import 主要套件、確認 GPU 可用），用 `@@VER` 標記回傳版本，顯示成表格。

## 7. 輸入、輸出與程式碼來源

- 小檔案：`files.upload()` 上傳，完成後顯示檔名與大小；結果用 `shutil.make_archive` 打包，`files.download()` 下載。
- 大檔案或要跑很久（可能斷線）：`drive.mount("/content/drive")` 掛載雲端硬碟，中間結果邊跑邊存到雲端硬碟，斷線後可以從中斷處繼續。
- 專案程式碼：少量腳本直接內嵌在格子裡（`script = r"""..."""` 寫成檔案再用 `/content/venv/bin/python` 執行）；程式較多時由使用者上傳專案 zip 或放雲端硬碟。私人 GitHub 倉庫要用 token 時，存在 Colab 左側「🔑 密鑰」，用 `google.colab.userdata.get()` 讀取，不寫進筆記本。

## 8. 存放與安全

- 筆記本放在專案的 `colab/`（例：`colab/layout_trial.ipynb`），跟程式一起進 Git；使用者用 Colab「檔案 → 上傳筆記本」開啟，或放雲端硬碟。
- 提交前清除輸出（Colab「編輯 → 清除所有輸出」，或骨架本身就沒有輸出），避免把檔名、路徑、執行結果帶進 Git。
- 金鑰、token 不寫進筆記本（見第 7 節）。公司專案的內部資料上傳到 Colab 前先問使用者。
- `metadata` 只保留骨架裡的欄位（`accelerator`、`colab.provenance`、`colab.gpuType`、`colab.toc_visible`、`kernelspec`、`language_info`），不要留下 `executionInfo` 等含使用者名稱的欄位。

## 9. 驗證

- AI 修改後：用 Python 讀 `.ipynb`（JSON 格式要正確），每個程式格 `ast.parse` 語法要通過；內嵌腳本另外 `ast.parse`。
- 實跑只有使用者能做：說明要在 Colab「全部執行」，預期每一步出現 ✅、最後下載 zip。
